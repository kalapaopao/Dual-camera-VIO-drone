# 项目交接文档：WSL2 Docker 双目 USB 摄像头

## 1. 项目目标

本项目用于在 Windows + WSL2 + Docker 环境中访问 USB 双目摄像头，完成：

- USB 摄像头通过 Windows `usbipd` 透传到 WSL2。
- WSL2 中生成 `/dev/video0` 和 `/dev/video1`。
- Docker 容器通过 V4L2 访问摄像头。
- 使用 GStreamer 检查采集链路。
- 使用 C++ 程序读取 MJPEG 双目拼接帧，并通过 HTTP 推送到 Windows 浏览器。

当前阶段不包含 YOLO、PyTorch、CUDA、RKNN、TensorRT 和 OpenCV。

## 3. Docker 环境

`Dockerfile` 使用 `ubuntu:22.04`，安装：

- build-essential、cmake、git、vim、nano、pkg-config
- v4l-utils、libv4l-dev
- GStreamer tools、base、good、bad、libav
- Python 3 和 pip

Compose 映射：

```yaml
privileged: true
devices:
  - /dev/video0:/dev/video0
  - /dev/video1:/dev/video1
volumes:
  - ./workspace:/workspace
ports:
  - "8080:8080"
  - "8081:8081"
```

## 4. 启动流程

### 4.1 Windows 透传摄像头

在 PowerShell 中：

```powershell
usbipd list
usbipd bind --busid 1-6
usbipd attach --wsl --busid 1-6
```

当前设备是 `0bda:5883 USB Camera`，但 BUSID 重新插拔后可能变化，必须以 `usbipd list` 为准。

### 4.2 WSL 检查设备

```bash
ls -l /dev/video*
```

预期：

```text
/dev/video0
/dev/video1
```

### 4.3 构建和启动容器

```bash
cd /home/kaka/tl3576_camera_driver/uav_vision_docker
docker compose build
docker compose up -d --force-recreate
docker compose exec uav_camera bash
```

如果镜像已经存在，可以直接：

```bash
docker compose up -d
docker compose exec uav_camera bash
```

注意：`docker compose start` 只启动后台容器，不会自动进入交互终端。

## 5. 摄像头验证

容器内执行：

```bash
ls -l /dev/video*
v4l2-ctl --list-devices
v4l2-ctl --list-formats-ext
```

当前摄像头可提供双目横向拼接格式，例如：

```text
1280x480
1920x540
2560x720
2560x960
```

其中 `1280x480` 通常是左右各一半的横向拼接帧。

无 GUI 的 GStreamer 测试：

```bash
gst-launch-1.0 \
  v4l2src device=/dev/video0 num-buffers=30 \
  ! image/jpeg,width=1280,height=480,framerate=60/1 \
  ! jpegdec \
  ! videoconvert \
  ! fakesink sync=false
```

## 6. C++ 程序

源码：`stereo_mjpeg_server.cpp`

程序特点：

- 使用 V4L2 MMAP。
- 读取 MJPEG，不依赖 OpenCV。
- 默认读取 `/dev/video0`。
- 默认参数为 `1280x480@60`。
- 提供 multipart MJPEG HTTP 服务。
- Windows 浏览器可直接打开视频流。

容器内编译：

```bash
cd /workspace
g++ -std=c++17 -O2 -Wall -Wextra \
    stereo_mjpeg_server.cpp -o stereo_mjpeg_server
```

启动：

```bash
./stereo_mjpeg_server /dev/video0 1280 480 60 8080
```

Windows 浏览器访问：

```text
http://localhost:8080/
```

如果使用第二个节点：

```bash
./stereo_mjpeg_server /dev/video1 1280 480 60 8081
```

说明：`/dev/video0` 和 `/dev/video1` 是同一 USB 双目设备暴露出的两个 V4L2 节点，不一定分别代表左目和右目。当前验证表明双目拼接帧可以从 `/dev/video0` 读取。

## 7. 文件持久化规则

持久化内容：

- Windows 本地工作区中的源码和文档。
- WSL 项目的 `workspace` 挂载目录。
- Dockerfile 和 docker-compose.yml。
- Docker 镜像本身。

不应依赖的内容：

- 只在运行中容器内部临时安装的软件。
- 只写在容器可写层中的临时文件。
- 容器内的编译产物。

`docker compose stop` 不删除容器，之后可以用 `docker compose start` 恢复。

`docker compose down` 会删除容器，但不会删除本地源码，也不会删除镜像；未挂载到 `/workspace` 的容器内部临时修改可能丢失。

## 9. 已知限制

- Windows 重启后通常需要重新执行 `usbipd attach --wsl`。
- 摄像头重新附加到 WSL 后，需要 `docker compose up -d --force-recreate`，因为旧容器不会自动获得新设备节点。
- 当前 Compose 没有设置 `restart: unless-stopped`，Docker 重启后需要手动启动容器。
- HTTP MJPEG 服务适合开发预览，不是生产级视频传输协议。
- WSL 中的 `F:\yolo\miniconda3` PATH 翻译警告与摄像头项目无关，属于 Windows PATH 被 WSL 导入时的环境警告。
